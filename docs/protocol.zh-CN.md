# 35inchNEW / Rev A 串口协议

[English](protocol.md) | 简体中文

适用于竖屏 320×480、横屏 480×320，不同硬件或固件版本可能存在差异。字节序列使用十六进制，坐标和尺寸使用十进制；B0 表示报文的第一个字节。

## 工作原理

电脑负责采集数据、绘制图像，通过串口向副屏发送报文。副屏按报文中的命令修改设置或更新画面。

每条报文都有一个 **6 字节命令头**，其中包含操作码和四个参数字段。需要额外数据的命令，会在命令头后追加**负载**。是否有负载、负载多长，由操作码及其参数决定：

```text
命令
├── 无负载：整条报文只有 6 字节命令头
│   ├── 零参数：复位、清屏、填黑、屏幕开关、探测
│   └── 带参数：亮度（数值放在命令头内）
└── 有负载：6 字节命令头 + 额外数据
    ├── 控制数据：方向、镜像
    └── 图像数据：RGB 位图、扩展图像格式
```

## 公共命令头

所有命令使用相同的编码。**字段的含义随命令变化，字段的位置和位宽不变。**

| 字节位置 | 内容 |
| --- | --- |
| B0–B4 | 四个 10 位参数字段，依次为 `x`、`y`、`end_x`、`end_y`。 |
| B5 | 1 字节操作码 `command`。 |

字段沿用绘图时的名称：位图命令中表示左上角、右下角坐标；亮度命令复用 `x` 存放亮度；不使用的字段置零。因此，**无负载不等于无参数**。

每个参数字段可编码 0–1023。本文以 `header(x, y, end_x, end_y, command)` 表示以下打包规则：

```text
packed = (x << 30) | (y << 20) | (end_x << 10) | end_y
B0..B4 = packed 的 5 字节大端表示（高位字节先发）
B5     = command
```

打包结果共 40 位；C/C++ 中须先将字段转换为 64 位无符号整数，再移位。负载不参与上述打包，其格式见各命令。

## 无负载命令

报文到 B5 结束，总长固定为 **6 字节**。

### 零参数命令

统一格式：`header(0, 0, 0, 0, command)`。

| 操作码 | 操作 |
| --- | --- |
| `0x65` | 复位。 |
| `0x66` | 清屏。 |
| `0x67` | 填黑。 |
| `0x6C` | 关闭屏幕。 |
| `0x6D` | 打开屏幕。 |
| `0xFF` | 连接探测；回复用于判断固件时序。 |

探测报文：`00 00 00 00 00 FF`。为兼容清屏命令，本项目先设为方向 0，发送 `0x66`，再恢复原方向。

### 带参数命令：亮度 — 0x6E

格式：`header(raw, 0, 0, 0, 0x6E)`。原始值 `raw` 为 0–255，0 最亮、255 最暗。百分比 `p`（0–100）的换算：

```text
raw = floor(255 × (100 - p) / 100)
```

示例：75% → 原始值 63 → `0F C0 00 00 00 6E`。亮度值已包含在命令头中，后面不追加数据。

## 有负载命令

命令头之后，从 **B6** 开始发送负载；总长度为 `6 + 负载字节数`。下文偏移均从整条报文开头计算。

### 控制数据

方向和镜像命令均使用零参数命令头，后接 **10 字节负载**，总长 **16 字节**。

#### 方向 — 0x79

命令头：`header(0, 0, 0, 0, 0x79)`。

| 负载位置 | 内容 |
| --- | --- |
| B6 | 十进制 `100 + direction` |
| B7–B8 | 宽度，16 位大端 |
| B9–B10 | 高度，16 位大端 |
| B11–B15 | 补零 |

| direction | 方向 | 宽 × 高 | B6 |
| --- | --- | --- | --- |
| 0 | 竖屏 | 320×480 | `64` |
| 1 | 反向竖屏 | 320×480 | `65` |
| 2 | 横屏 | 480×320 | `66` |
| 3 | 反向横屏 | 480×320 | `67` |

横屏完整报文：`00 00 00 00 00 79 66 01 E0 01 40 00 00 00 00 00`。

#### 镜像 — 0x7A

命令头：`header(0, 0, 0, 0, 0x7A)`。负载 B6 为 `00`（关闭）或 `01`（开启），B7–B15 补零。

### 图像数据

图像命令在命令头中指定绘制位置，在负载中提供颜色或像素数据。以下各格式的字节序独立定义。

#### RGB 位图 — 0xC5

用于全屏和局部更新。坐标原点在左上角，x 向右、y 向下；矩形包含右下角端点，且必须位于当前屏幕范围内。

```text
命令头：header(x, y, x + width - 1, y + height - 1, 0xC5)
负载：  width × height × 2 字节
顺序：  从上到下逐行，每行从左到右
```

每像素为 RGB565（红 5 位、绿 6 位、蓝 5 位），按**小端**发送（低位字节先发），不含文件头、透明度或行尾填充。8 位 RGB 通道的转换公式：

```text
rgb565 = ((r >> 3) << 11) | ((g >> 2) << 5) | (b >> 3)
bytes  = [rgb565 & 0xFF, rgb565 >> 8]
```

| 颜色 | RGB565 | 发送字节 |
| --- | --- | --- |
| 红 | `F800` | `00 F8` |
| 绿 | `07E0` | `E0 07` |
| 蓝 | `001F` | `1F 00` |
| 白 | `FFFF` | `FF FF` |
| 黑 | `0000` | `00 00` |

全屏负载均为 **307200 字节**，整条报文为 **307206 字节**。

| 尺寸 | 矩形范围（含端点） | 命令头 |
| --- | --- | --- |
| 320×480 | (0, 0)–(319, 479) | `00 00 04 FD DF C5` |
| 480×320 | (0, 0)–(479, 319) | `00 00 07 7D 3F C5` |

示例：在 (10, 20) 绘制红色 2×1 矩形，终点为 (11, 20)。前 6 字节为命令头，后 4 字节为两个红色像素：

```text
02 81 40 2C 14 C5 00 F8 00 F8
```

#### 扩展：同色点列表 — 0xC3

已知布局，总长 **64 字节**（6 字节命令头 + 58 字节负载）；不保证所有 Rev A 固件支持。

```text
B0..B5 = header(base_x, base_y, coord_byte_count, 0, 0xC3)
B6..B7 = RGB565 颜色，大端（高位字节先发）
B8..   = dx0, dy0, dx1, dy1, ...
```

`coord_byte_count` 为有效坐标字节数，必须是偶数，最多 56 字节（28 个点）。每个坐标分量占 1 字节，尾部剩余字节不是坐标。坐标相对基准点解释，固件实际绘点行为仍待确认。

#### 扩展：单色位图 — 0xC6

已知布局，不保证所有 Rev A 固件支持。矩形头与 `0xC5` 相同，命令改为 `0xC6`。负载为连续打包的像素，每像素 1 bit，每字节先高位、后低位。

已知尺寸：68×90 → 765 字节负载；48×66 → 396 字节负载。无颜色字段，位值对应的颜色及背景处理尚未确认。

## 传输约定

- **串口参数**：115200 波特率，8N1（8 位数据位、无校验、1 位停止位）。DTR、RTS 置位，关闭硬件及软件流控。
- **报文边界**：无起止标志、独立长度字段、序号或 CRC。USB 分包不代表报文边界。
- **发送顺序**：命令头与负载之间不能插入其他命令；普通位图传输不等待逐帧 ACK。

探测回复包含 ASCII `V2` 时使用 V2 时序；否则使用 V1：

| 发送位置 | V1 等待 | V2 等待 |
| --- | --- | --- |
| 方向 / 镜像命令之后 | 10 ms | 10 ms |
| RGB 位图命令头之后、像素之前 | 10 ms | 无 |
| RGB 位图负载之后、下一条命令之前 | 10 ms | 无 |

实现见 [src/device.cpp](../src/device.cpp)，字节对照测试见 [protocol()](../tests/core_test.cpp)。
