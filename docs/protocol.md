# 35inchNEW USB 串口协议

目标是官方软件中 Rev A 的 320×480 / 480×320 设备，不适用于所有 TURZX 硬件版本。参考 Python 仓库的 `library/lcd/lcd_comm_rev_a.py`，最终以官方串口发送调用及缓冲区布局为依据。

串口为 115200、8N1，DTR/RTS 为 true，硬件流控关闭。官方正常绘制没有 CRC、序号或逐帧 ACK。

六字节头：前五字节是大端的 40 位坐标字段，最后一字节是命令。

```
packed = (x << 30) | (y << 20) | (end_x << 10) | end_y
header = packed.to_be_bytes()[3..8] + command
```

| 命令 | 含义 | 数据 |
|---|---|---|
| 0x65 | 复位 | 六字节控制头 |
| 0x66 | 清屏 | 官方清屏方向依赖竖屏；程序随后恢复用户方向 |
| 0x67 | 黑色填充 | 六字节头 |
| 0x6C / 0x6D | 关闭 / 打开屏幕 | 六字节控制头 |
| 0x6E | 亮度 | x 为原始值：0 最亮、255 最暗 |
| 0x79 | 方向 | 16 字节；第 6 字节为 100+方向，7–10 为宽高的大端 u16，其余补零 |
| 0x7A | 镜像 | 16 字节；第 6 字节为布尔值 |
| 0xC5 | RGB 位图 | 包含末端坐标，随后 RGB565 小端，逐行从左到右 |
| 0xC3 | 同色点集合 | 64 字节包；颜色为大端 RGB565，随后相对坐标 byte 对，最多 28 点 |
| 0xC6 | 单色位图扩展 | 每字节从高位到低位展开 |
| 0xFF | 官方连接探测 | `00 00 00 00 00 FF` |

方向编号：0 竖屏、1 反向竖屏、2 横屏、3 反向横屏。

全屏头示例：320×480 为 `00 00 04 FD DF C5`；480×320 为 `00 00 07 7D 3F C5`。像素数据长度均为 307200 字节。红、绿、蓝的 RGB565 字节分别为 `00 F8`、`E0 07`、`1F 00`。

V1 在位图头和像素之间、发送完成后各等待 10 ms；V2 去掉这两处等待。方向和镜像命令之后仍等待 10 ms。串口仅由一个工作线程持有，控制包与位图像素不会交叉写入。

软件通过 C5 发送合成图像，并对变化区域做矩形更新。这能实现主题显示，不依赖仍未完整确认的 C2/数字绘制扩展。

Python 对照：坐标打包、亮度映射和位图像素规则一致；Python 额外的六个 0x45 HELLO 是识别机制，官方 FF 探测采用另一个包。Python 的 RTS/CTS 设置和 Clear 固定方向行为不能直接等同于官方实现。

本地 `../analysis/verify_rev_a_comparison.py` 已执行 8 个固定案例和 1000 组随机头部比对。当前环境仅枚举到 COM1，没有匹配的实体副屏，USB 实屏收发尚待验证。
